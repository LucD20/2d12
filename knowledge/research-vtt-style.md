# VTT style: how Foundry systems and other VTTs draw sheets, chat cards and previews

## 2026-11-17: for the Foundry look (fitting the book while keeping every function)

**The question.** How do Foundry VTT game systems (and other VTTs) style their sheets, chat cards and item or ability previews, how closely do they match their printed books, and what do players and designers say works for readability and speed in a VTT? Covered: the major Foundry systems against their books (what their code and their own notes show); Foundry V12-V14 theming facts (themes, CSS layers, chat structure); readability in a narrow chat log; matching a book on screen; accessibility facts for a dark UI. The printed-book look is in `card-look-published-books.md`, `book-typography-serious-tone.md` and `rpg-layout-craft.md` (WCAG 1.4.1 and 1.4.3, the BDA guide and NN/g's summary of the light-against-dark studies are there): not repeated here.

**How far to trust this file.** One pass, by an agent (about 60 steps); not re-checked by a second. No raw report: everything found is here. **The big gap:** players' own opinions of these looks live mostly on Reddit and Discord, which this session could not read (Reddit refuses readers; a Reddit mirror was blocked; the Foundry forum's search did not answer). So the community's verdicts below come mostly from **what people built and published to fix things** (alternative sheets, chat-compacting modules, theme modules: their own package descriptions), from release notes and from a few forum posts. Treat "players say" as thin.
- [read] = read in full on its page, or in the system's own source code (cloned from GitHub, Nov 2026), or seen in an image actually opened: Foundry's release notes (13.333, 13.334, 13.340, 13.341, 14.352 to 14.359), the V14 API page `GameUIConfiguration`, the community wiki's *CSS Cascade Layers* and *ApplicationV2* guides, the source of dnd5e 6.1.1, pf2e (Nov 2026), Draw Steel 1.2 and Foundryborne Daggerheart 2.12.9 (stylesheets, manifests, language files, changelogs, wikis), the dnd5e 3.0.0 release notes (through a mirror, newreleases.io, since GitHub's own pages were blocked), two screenshots (dnd5e's chat log and roll windows; Draw Steel's monster embed), package pages on foundryvtt.com, WCAG 2.2's *Understanding* pages for 1.4.4 and 1.4.11, Roll20's blog.

## Q1. Foundry systems and their look, against their books

**dnd5e (official, by Foundry with Wizards of the Coast)** [read: release 3.0.0 notes, the 6.1.1 source, the wiki].
- **The redesign is 3.0, not 4.0.** 3.0.0 (for Foundry V11; the release that marked the system becoming official, early 2024 by the partnership's date) "includes a completely redesigned character sheet [...] to include some official branding and a fresh new look". Its main idea is a **Play / Edit toggle**: "In 'Play' mode, the sheet is optimised for normal play [...] Things like adjusting ability scores or skill proficiencies can only be done when switching to 'Edit' mode [...] this allow[s] for some of the clutter required to display editing controls to be hidden away during normal use". Also "Rich Tooltips", a Favourites area "for weapons, spells, features, or skills the character frequently uses", and chat cards "given a new coat of paint [...] aimed at speeding up gameplay": an effects tray, targets shown with their AC, damage "grouped by damage types". A dark sheet was then only a promise ("we are committed to providing dark mode versions for our sheets").
- **Now (6.1.1):** both themes, built from variables scoped `@scope (.theme-dark) to (.themed)` and the same for light. The light theme is grey and red paper textures; the dark theme a "denim" texture with dark banner art per sheet type (`banner-character-dark.webp`...). Fonts: Roboto for text and chat, Roboto Slab for block headers and the sender's name (bold small caps), Modesto Condensed for display titles. A **high-contrast flag** (`dnd5e-flag-high-contrast`) strengthens borders and drops faded states on sheets, in both themes.
- **Chat settings it offers** (its language file): **Chat Log Theme** ("Specify a theme for the chat log. By default this will inherit from the Application theme": Default / Dark / Light); **Collapse Item Cards in Chat** ("Automatically collapse Item Card descriptions"); **Collapse Trays in Chat** (damage, hit and effect trays: Collapse All / Collapse Older Trays / Collapse After Use / Never Collapse); **Summary Chat Cards** ("Append certain results as summaries rather than full chat cards"); hiding attack results and NPC descriptions from players. 3.0 also moved chat card sizes to rem "so they appropriately scale with the font size slider" (#1413).
- **Its own screenshot convention** (wiki, *Contributing*): "All screenshots should be taken with the **Interface** setting in Dark mode and the **Applications** setting in Light mode". The screenshot opened (the Attack activity page) shows exactly that: a near-black sidebar holding **light parchment-textured cards**. One attack makes **three cards**: the usage card (portrait, item name, "Attack", dotted-outline tags Weapon / Martial / Melee / Sap / Action / Reach 5 ft / Proficient, two round buttons), the attack roll (formula line, a large bold total "12" with an expand arrow) and the damage roll (total "14", a collapsed "APPLY" tray). The roll windows are light parchment with a big serif title, the die drawn as an icon, a "CONFIGURATION" box and three wide buttons in capitals (ADVANTAGE / NORMAL / DISADVANTAGE).
- **Reception, from what was built:** **Tidy 5e Sheets** (a full replacement sheet, rewritten again for dnd5e 5.x, nine tabs by default) [lead: its release notes through search]; **Compact DnDBeyond 5e Character Sheet**: "for the players who like D&DBeyond's layout, but want it to fit in a space more foundry-friendly [...] Making resources always present. Making the skill list always present" [read]; **Small Talk**: "makes dnd5e chat messages smaller by reducing overall size, button size, margins, portrait size, subtitle size", with options to hide portraits, subtitles and item images, "Purple Whispers [...] to better distinguish them from public messages", "Blue Hit Checks [...] (may be more red-green colorblind friendly)" [read]; **Zeta's Smaller Chat**: "makes the 3.X.X chat cards smaller" [read]. A Reddit thread "Less cluttered chat" (Apr 2025) [lead]: a moderator pointed to the two collapse settings; others to a UI module with smaller buttons and a dark chat.

**Pathfinder 2e (pf2e, community system with Paizo's licence)** [read: the source, Nov 2026].
- No theme setting of its own: it follows core's light / dark. Light uses core's parchment texture (`--background: var(--parchment-texture)`); the changelog has fixes for both ("Fix light mode parchment backgrounds", "Fix colors of whisper and blind inline rolls in dark mode").
- Fonts: Gelasio as the body serif, Eczar as a display serif, Roboto and Roboto Condensed, Modesto Condensed, and a glyph font for the action symbols (`Pathfinder2eActions`). Whether these match the printed book's faces was not checked.
- **Trait tags** reproduce the book's trait boxes: a `micro` style (10 px, sans, uppercase, letter-spaced 0.05em), white text on the primary maroon (`#5e0000`), rarity colors (uncommon `#98513d`, rare `#002664`, unique `#54166e`), a 2 px radius, an inset 1 px dark edge.
- **Reception, from what was built:** **PF2e Dorako UI** (verified for V14): it "standardizes the Foundry UI, Pathfinder 2e System sheets, and all your modules [...] to a pretty combination of glass, red, and blue"; features include "Use dark theme messages for GM and light theme for players", "Chat message accesibility: Label indicating whispered messages and secret rolls; Label for Player names", "Chat message simplification: Pull important spellcasting information out of the footer and into the main message; Remove attack-related tags from damage rolls to save space", a "'Compact UI' mode that fades out UI when inactive", "Dalvyn's CRB-styled journal theme", and a list of applications "incompatible with dark theme (or _requiring_ dark theme)" [read, its package page]. **Accessibility Enhancements**: "High Contrast Character Sheets [...] which remove all coloured elements from the character sheets and maximise contrast, prioritising readability over aesthetics. There is a dark and light mode option" [read]. **Pathfinder UI**: "Dark Mode Player Sheet Option" [read]. **Phil's PF2e RealDark**: replaces "bright parchment textures" with dark backgrounds "for long night sessions" [lead: its page did not load].

**Draw Steel (MCDM's licensed system, MetaMorphic Digital)** [read: the 1.2 source, changelog, wiki, one image].
- **Fonts chosen for reading:** core's `--font-primary` is replaced by **Atkinson Hyperlegible** (the Braille Institute's legibility face); Newsreader (a serif) for h2-h3 and journal text; "Draw Steel Book" for h1 titles; a "Draw Steel Glyphs" font for the tier and characteristic symbols.
- **Looks like the book where the book is read:** "Implemented a Draw Steel Journal Sheet that styles the contained pages in a fashion similar to the core books" (0.9/0.10). The monster **embed** opened is a re-drawn stat block: a header (name, kind, level and role, EV), a row of five big numbers (Size, Speed, Stamina, Stability, Free Strike), weaknesses and immunities in two columns, the five characteristics each with a **black square initial** (M, A, R, I, P), then each ability with an icon, "Keywords" and "Type" as labeled pairs, distance and target with small icons, "Power Roll + Presence" and the three tiers as **tier glyphs** (≤11, 12-16, 17+) in outlined boxes, light grey background, thin rules and a small notch between blocks. Light theme, flat, no texture.
- **Chat:** "[BREAKING] Re-implemented system generated chat messages to use a parts system [...] Many actions that would generate new chat messages instead append to an existing message, such as spending a hero token" (0.9); "Long enricher or roll text will now wrap in the chat log"; damage and effects applied from buttons on the message ("Apply Damage", "Apply Effect", to selected tokens). "Significant overhaul of application styles across the system" (1.2). Its manifest puts its CSS in three core layers (system, variables, elements).
- **Players** [checked, EN World Draw Steel thread, 2025-2026]: a module, Draw Steel Plus, "does at least make the 'Characteristics' always visible so you can click them while looking at any other tab"; "I do like the Draw Steel Plus monster sheet layout way, way more than the default"; on choosing between Foundry and MCDM's own Codex VTT: "Codex does a good job of automating the system - like popping something up when a player or GM can use a reaction or showing how far a push can go".

**Daggerheart (Foundryborne, the official Foundry system)** [read: package page, source, language file].
- Sells its look: "inspiring visuals for the sheets, chat and more". Its Appearance settings include **"Auto-expand Message Sections"** chosen part by part (Description / Formula / Damage-Healing / Target), "Auto-expand Descriptions" per sheet type, "Pip Display For Resources", a "Tooltip Card Theme", and where the Fear tracker sits.
- **Alternative: Daggerheart Sleek UI** [read]: "Clean and organized layout with usability and readability improvements"; "Interactable resources [...] with left and right click"; "Easily readable resource pips"; "Clickable damage thresholds"; "Toggleable and persistent category headers to improve space usage"; "Mini Sheets [...] at the bottom of the screen when their token is selected"; "Changes to Foundryborne's default styling and chat cards".

**Shadowdark, Lancer, Old-School Essentials, Dragonbane, Blades in the Dark.** Package pages read for Shadowdark, Lancer and Blades: they list content and automation, nothing on their look. OSE's and Dragonbane's pages did not load. No reception of their look was found. Not covered.

**Call of Cthulhu 7e:** a module exists only to restyle its chat: "make CoC7 chat cleaner, more compact, and easier to read while preserving the system's native behavior" (Foundry 13-14) [read].

## Q2. Foundry V12-V14 theming facts (only what was read)

- **Theme V2 and two color schemes.** V13 notes (13.341, Apr 2025): the interface "now automatically adapt[s] to the settings from your operating system or browser [...] This preference can be overridden with a world-level setting"; "The chatlog maintains a cleaner display of its cards without a background"; the sidebar is "a 'cabinet' style [...] collapsed by default in order to draw the eye to the canvas"; "a minimalist chat notifications tray will show the previous few messages". The V14 API (`GameUIConfiguration`, 14.370) stores `colorScheme: { applications: "" | "dark" | "light"; interface: "" | "dark" | "light" }` plus `chatBackground` (boolean), `chatNotifications` ("cards" | "pip"), `fontScale`, `uiScale` and the fade settings. So **windows (applications) and the frame (interface: sidebar, chat, HUD) take separate themes**; "" is the default (following the browser, by the notes). [read]
- **Per-sheet theme.** 13.334: "you can also override the default theme of any individual sheet". 13.333: "Arbitrary UI elements can now include theme-specific boilerplate variables via use of the .themed class in conjunction with the specific theme to apply" (#11812). [read]
- **The chat log is the exception.** 13.340: "the entire application (perhaps with the exception of the Chat Log) is now automatically styled to match your computer's theme preferences"; "Popped out Chat messages are now forced to a light theme instead of a mix of light and dark themes" (#12500); the token HUD and ruler labels got light-mode styles (#12479, #12387). V14 fixed "the color-scheme css property [...] for the #interface and #hud elements" (14.354) and added light styles for `<hr>` and the chat input (14.353). [read]
- **CSS layers.** 13.341: "we've migrated entirely to using CSS Layers for Foundry VTT-controlled UI elements [...] This lets everyone [...] be a little less specific with their CSS selectors". The community wiki (current to 13.334) lists the declared layers, lowest first: `reset, variables, elements, blocks, applications, compatibility, layouts, system, modules, exceptions` (nested ones such as `variables.themes`, `elements.typography`, `blocks.ui`). "If you include your CSS the normal way, by listing it in your manifest [...] Foundry v13 and later will automatically import it into either the module or the system layer"; `system` beats every core layer and `modules` beats `system` ("the intent is that modules can override systems"); a manifest entry can name a layer (`{"src": ..., "layer": "variables"}`) or `null` (unlayered, beating everything, "will not play nicely"). Core sets heading color in `elements.typography` from `--color-text-emphatic`; a system can opt out with `all: revert-layer`. [read]
- **How three systems theme in practice** [read, their source]: dnd5e and Draw Steel define their colors as variables inside `@scope (.theme-dark) to (.themed)` / `(.theme-light)`; pf2e uses `body.theme-light .application:not(.themed), .themed.theme-light`. dnd5e wraps its variables in `@layer variables`; Draw Steel ships three files into the `system`, `variables` and `elements` layers.
- **ApplicationV2.** The wiki: introduced in V12 with "Native light/dark mode support" and "Better application window frames"; Application V1 survives until V16. Its debugging macro flips `uiConfig.colorScheme.applications` and `.interface` together. V13 converted every core window to AppV2 (13.340). [read]
- **Chat message structure** (as dnd5e's chat CSS targets it, not a core document): `.chat-log` / `.chat-popout` > `.message` > `.message-header` (`.message-sender`, `.message-metadata`, `.whisper-to`) and `.message-content`; whisper / blind / emote are classes on `.message` (dnd5e marks them with a colored 3 px bottom border). V14 replaced roll modes with "Chat Message Visibility Modes [...] can modify the visibility of any message (not only dice rolls)" and an "In-Character" mode (14.355); chat bubbles now default to messages without rolls (14.366, lead through search). [read except where marked]

## Q3. Readability and speed in a VTT

- **The chat card is where the complaints are.** Every big system has an add-on to make its cards smaller (dnd5e: Small Talk, Smaller Chat; CoC7: Evil CoC7 Card; pf2e: Dorako's "Chat message simplification"). What they cut, in their words: "overall size, button size, margins, portrait size, subtitle size"; "attack-related tags from damage rolls"; key spell facts moved "out of the footer and into the main message". [read]
- **The systems' own answers:** collapse the long parts by default, and let the user choose which (dnd5e's item descriptions and trays, with "Collapse Older Trays"; Daggerheart's Description / Formula / Damage / Target expanded or not); **summaries instead of full cards** (dnd5e); **append to one message instead of posting new ones** (Draw Steel's chat parts); wrap long text (Draw Steel). [read]
- **Sheets: keep the things clicked every turn always on screen.** Draw Steel Plus ("Characteristics always visible"); Compact DnDBeyond ("resources always present", "skill list always present"); dnd5e's Favourites; Daggerheart Sleek's mini sheets at the screen's bottom and clickable thresholds; dnd5e's Play mode hides editing controls ("clutter"). [read / checked]
- **Whispers and secrets need words, not only a tint:** Dorako adds a "Label indicating whispered messages and secret rolls"; Small Talk's "Purple Whispers" also "labels them". [read]
- **Text that scales:** dnd5e moved chat cards to rem units so they follow the core Font Size slider (`fontScale`); Draw Steel fixed a sheet tab "on larger core font sizes". Measured sizes in the code: dnd5e chat text 13 px, metadata 10 px, sender 14 px; pf2e trait tags 10 px uppercase. [read]
- **Not found:** a measured chat-log width (the "about 300 px" stays unverified), a designer's essay on chat-card design, any test of card size against play speed.

## Q4. Matching the book on screen

- **Where systems copy the book, it is the reference views:** Draw Steel's journal pages and monster embeds (book-like stat block, the book's tier glyphs); pf2e's trait boxes (the book's maroon); Dorako's "CRB-styled journal theme"; dnd5e's "official branding" and banner art. The working surfaces (chat, roll dialogs, sheets in play) are plainer and app-like in all four. [read]
- **Light card on a dark frame is the default and the documented look of the biggest system** (dnd5e's "Interface Dark, Applications Light"; the screenshot). Foundry forces popped-out chat messages to light. Dorako offers "dark theme messages for GM and light theme for players". [read] Whether players like the mix: no opinion found.
- **Dark is wanted:** Roll20's dark mode was "our #1 most voted Suggestions & Ideas topic with well over a thousand votes" (Sep 2022) [read]. pf2e and dnd5e users built dark sheets before the systems had them (Pathfinder UI, RealDark; dnd5e 3.0 promised one) [read / lead].
- **The failure to avoid: a light parchment under a theme switch.** Roll20 forum (date not shown) [checked]: on the Shadow of the Demon Lord sheet, "When Dark Mode is on the text auto flips to lighter gray [...] because of the light tan parchment color [...] the text flipping actually ends up making the legibility way worse"; the answer: "the vtt will make changes to colors it recognizes (true black or white as specified in the code). Anything else will be left alone". A Roll20 staffer in 2022 on roll templates without a dark mode: "still destroying readability" [lead]. Foundry's own V13-V14 notes are a list of the same kind of fixes (invisible scene-navigation icons in light theme, `dt` text color, ruler labels). [read]

## Q5. Accessibility facts for a VTT UI

- **WCAG 2.2, 1.4.11 Non-text Contrast** [read]: "Visual information required to identify user interface components and states" needs "a contrast ratio of at least 3:1 against adjacent color(s)" (button edges, checkbox and pip states, focus), except inactive components. **1.4.4 Resize Text** [read]: "text can be resized without assistive technology up to 200 percent without loss of content or functionality". (1.4.1 color alone and 1.4.3 text contrast 4.5:1: in `rpg-layout-craft.md`.)
- **What VTT authors shipped for it:** high-contrast sheet modes that drop color (dnd5e's flag; Accessibility Enhancements: "remove all coloured elements [...] prioritising readability over aesthetics"); blue instead of green for success "(may be more red-green colorblind friendly)"; a legibility typeface as the base font (Draw Steel); labels for whisper / secret states; rem sizing under a global font slider. [read]
- **Dark-theme design rules** (avoid pure black, desaturate accents, lighter surfaces for raised elements: Material Design) [lead: from memory; its pages would not render here].

## Takeaways

1. **Foundry gives two separate switches, windows and frame**, plus a per-sheet override; the chat log is the special case (popped-out messages forced light; dnd5e adds its own Chat Log Theme setting).
   - *For 2d12:* a note only: "dark by default" can mean the frame, the windows, or both; Foundry stores them apart.
2. **The biggest system's documented look is a light card on a dark frame** (dnd5e: Interface Dark, Applications Light).
   - *For 2d12:* a note only: a cream card inside a dark sidebar is the common Foundry picture, not an oddity.
3. **System CSS goes in the `system` layer automatically and beats core; modules beat systems.** Colors are best declared as theme-scoped variables (`@scope (.theme-dark) to (.themed)`), as dnd5e and Draw Steel do.
   - *For 2d12:* a note only: matches the project's generated `theme.css` approach; layering was not checked against it.
4. **Chat cards draw the most "too big" fixes.** The cuts people make: margins, portraits, button size, repeated tags, footers; the systems' answers: collapsed sections by default (user's choice per section), summaries, appending to one message.
   - *For 2d12:* a note only: size and repetition, not color, are what the add-ons attack.
5. **Speed on sheets = the per-turn controls always visible** (characteristics, resources, skills, favourites, mini sheets) and editing hidden in a separate mode.
   - *For 2d12:* a note only: a style pass that keeps every element is compatible with this; it is a layout point, not a color one.
6. **Book-matching is done in reference views** (journal pages, stat-block embeds, trait boxes, glyph fonts); working views stay plainer in every system seen.
   - *For 2d12:* a note only: Draw Steel's embed is the closest model of "a sheet is a printed stat block".
7. **Parchment textures are the thing dark-theme modules remove first**, and a light-parchment surface whose text color flips under dark mode is the classic legibility bug.
   - *For 2d12:* a note only: a light card must pin its own text color whatever the theme.
8. **State needs a word or label, not only a tint** (whispers, secrets, hits); contrast rules reach UI edges (3:1) and text must survive a 200% scale.
   - *For 2d12:* a note only: same rule as the book's "words not color for frequency".
9. **Fonts:** dnd5e (Roboto, Roboto Slab, Modesto), pf2e (Gelasio, Eczar, Roboto), Draw Steel (Atkinson Hyperlegible, Newsreader): a sans for working text in all three, a serif for headings or reading text.
   - *For 2d12:* a note only: none of the three sets its chat in a book serif.
10. **Dark is a demanded feature** (Roll20's top request; community dark sheets before official ones), but no source compared reading speed on dark against light in a VTT.
