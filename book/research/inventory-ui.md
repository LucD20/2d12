# Inventory UI: how Foundry systems lay out a character's items and an NPC's loot

## 2026-11-19: for the PC sheet's Inventory tab (the Items tab renamed) and the NPC's Loot tab

**The question (Lucas).** The PC sheet's "Items" tab becomes "Inventory", a compact inventory; then the NPC's "Loot" tab in the same look. How do Foundry systems lay out and run an inventory (Pathfinder 2e, D&D 5e, Draw Steel, Daggerheart and others), and what do players and GMs like or dislike (compactness, clicks to equip or use, encumbrance, containers, loot from NPCs to PCs)? Layout and interaction only, not the games' rules. Drawing, stowing and hands in combat are in `gear-and-hands.md`: not repeated. How these systems style their sheets in general (themes, chat cards) is in `vtt-style.md`.

**How far to trust this file.** One pass, by an agent; not re-checked by a second.

### Takeaways

**Layout: the row**
1. **Every system draws the inventory as one-line rows under section headers that double as column headers.** dnd5e: the section's header carries the column labels (Price, Weight, Quantity, Uses, controls); pf2e: each section's header says Value / Qty / Bulk and holds the section's own **+ (create)** and **search (browse compendium for this type)**; Draw Steel: Kit (Melee bonus, Ranged bonus) then each Treasure kind (Echelon, Quantity); Daggerheart: a legend per section with a + on it. [read]
2. **The row is: small image, name (with a muted subtitle line in dnd5e), then a few narrow number columns, then the state toggles, then the edit / delete controls.** dnd5e's columns have fixed widths (Quantity 70 px, Weight 60, Price 80, controls 70) and a **priority**: when the sheet is too narrow, low-priority columns hide first (price at 300 goes before weight at 400, quantity at 500; the controls and capacity never go). [read]
3. **The description lives behind the row, not on it.** dnd5e: a click expands the row in place (description, then the item's activities as sub-rows with their own Use); pf2e: clicking the name toggles a summary under the row; Draw Steel: a chevron opens the item's embedded card in place. No system shows the full text on the row. [read]
4. **Clicking the image or name is the item's main verb.** dnd5e: the name is a button whose action is the item's use (roll or activate); pf2e: the image sends the item to chat (a chat icon appears over it on hover), the name opens the summary; Daggerheart: the image uses the item if usable, else posts it to chat, else opens it. [read]

**State: equipped, held, worn, stowed**
5. **pf2e puts the whole carry state in one icon on the row**, which opens a small menu: Held in 1 hand, Held in 2 hands, Worn (in its slot), Worn, Stowed (only if a container exists), Dropped. The icon itself shows the state (a fist with a 1 or a 2, a shirt, a box, a line for dropped). Invested is a second toggle (a gem) beside it, shown only for items that can be invested. [read]
6. **dnd5e and Daggerheart use plain on/off toggles** (an equip shield, an attune sun; Daggerheart an equip toggle and a "versatile" toggle for weapons). dnd5e shows these state toggles in **play mode** and swaps them for edit / delete in **edit mode** (the sheet's lock): during play the row has no delete button to hit by mistake. [read]
7. **Modules that replace the list with a paper doll or a grid (Enhanced Inventory, Equipment Paper Doll) equip by dragging into a slot.** Their own pages pitch space over weight ("you have to manage actual space"). They are add-ons for players who want inventory as a minigame, not the systems' choice. [read: the package pages]

**Quantity, currency, weight**
8. **Quantity is edited on the row**: dnd5e a text field between − and + (it also takes "+2" or "-1" typed), pf2e − and + around the number (shift or ctrl change the step), Draw Steel − and +, Daggerheart a number field. dnd5e and pf2e also split a stack (a split dialog; pf2e's transfer dialog asks how many when the stack is 2 or more). [read]
9. **Currency is one line above the list** (dnd5e: one small field per coin with a coin-manager button; pf2e: the coins, add / remove buttons, sell all treasure, distribute coins, then total coin and total wealth; Daggerheart: a gold line). Draw Steel has no currency and no weight at all: its Equipment tab is kits and treasures only. [read]
10. **Encumbrance is a thin bar with a number** (dnd5e: value / max with two breakpoints; pf2e: Bulk value / Encumbered at / Max, and Invested n / max, as a summary under the list). Containers show a capacity bar (dnd5e as tiles above the list; pf2e as a bar under the container's row, its contents nested and collapsed under a box icon). [read] **Players' view [checked]:** encumbrance "gets constantly ignored because it's a pain to track", even a digital sheet that sums it changes little; "I don't want to take a pause in my game while the players do a bunch of math"; slots are preferred to weights. Shadowdark's Foundry system tracks gear slots for the player [lead].

**Adding and finding**
11. **Adding is per section and quiet**: a + and a browse icon in the section header (pf2e), a + in the legend (Daggerheart, Draw Steel in edit mode only). Search sits above the list (pf2e: a search field; dnd5e: filter, sort and group controls; Daggerheart: search and filter). **Drag and drop** from the compendium or the sidebar is the main way items arrive in every system. [read]
12. **Right-click (or a ⋮ button) holds the rest**: dnd5e's context menu has Edit, Duplicate, Delete, Attune, Equip, Charge; Draw Steel and Daggerheart a ⋮ menu. The row keeps only the one or two verbs used every session. [read]

**Loot: NPC to PC**
13. **pf2e: a dead NPC's sheet becomes a loot sheet** (a world setting, "Upon their demise, NPCs become lootable by players"): players may open it; it shows only the inventory under the token's name marked [Dead]. A Loot actor can pull the items of selected tokens ("loot NPCs"). Moving an item between actors opens a transfer dialog (Move, Gift, Purchase; how many). [read]
14. **The community built the rest as modules, which says the default lacked it:** Item Piles (drop items on the map as piles, split loot between players, merchants), Looter (after combat a three-column window, Enemies | Players | Loot, drag items onto players, drag back), Easy Loot and Kel's Utilities (a 0 HP combatant becomes a pile), Shadowdark Extras (an NPC Inventory tab: "track NPC weapons, armor, and treasure, and record GP, SP, and CP for players to loot"; multi-select; a party stash). [read: the package pages] The recurring wish (inferred from what they build, not quoted): loot taken in one move, with a count, and announced in chat.
15. **Compact sheets are a genre of their own:** Tidy 5e ("fully expandable containers", "easy to expand items", "quick edit with middle click, open with double-click", custom sections, a responsive design) and Compact DnDBeyond exist because the default sheets felt roomy. [read: README and package page]

### How it applies to 2d12

**What the Items tab has now** (`foundry/twod12/templates/actor-sheet-pc.hbs`, tab `items`; `module/pcsheet.mjs` "Items tab"): three blocks with their own layouts. **Weapons**: a card-like row (name, Unloaded / 1H chips, a sub line of group, properties, subtype and range; the three Tiers; Mastery n / 4 and Technique locked or unlocked; a three-button segment Dropped / On you / In hand). **Armor**: name, Trained or Untrained, "Armor value n → AD n · Ward +n", the same segment. **Gear and loot**: a grid row (image that sends to chat, name, a quantity field, weight, cost, edit and trash icons), with "Coins [field] · Weight n" in its header. Two buttons at the top, "Generate Weapon" and "New Item". The NPC's Loot tab: a note, rows Item | Qty | "Give to a PC" (a pick window; it moves the whole stack), a "Drag items here" box.

**The mapping:**
- **One row grammar for the three blocks** (takeaways 1, 2): name (and a muted sub line) on the left, a few right-aligned figures, the state word, the controls last. The section header is a ruled line with the section's name and its column words in small text: that is the stat block's header line, not a box. Weapons, Armor, Gear (and Containers later) as sections; the Coins line above them, as pf2e and dnd5e do (takeaway 9).
- **At 540 px, choose the columns, don't squeeze them** (takeaway 2): dnd5e drops columns by priority; 2d12 can decide them once. Suggested: Weapons = name · where · the Tiers' damage on one short line · Mastery; Armor = name · AD / Ward · where; Gear = name · Qty · Weight. Cost and the weapon's properties go to the expanded row.
- **The detail behind the row** (takeaway 3): the card face of the item (CARD-ONE's model) opens under the row on a click, as Draw Steel embeds its cards. The Technique's lock, the properties, the cost, the description live there; the row stays one line (two for a weapon at most).
- **Where it is: one word, one menu** (takeaway 5): the three-button segment is the "pill" look STYLE-3 dislikes and costs width. pf2e's single state control fits better: the row shows one word (*In hand 1H*, *In hand 2H*, *On you*, *Dropped*) and a click opens the same menu as the HUD's hand tile (`handMenuModel` in `pcsheet.mjs`), so the inventory and the HUD set the hands the same way, with the same costs ("free" out of combat). The Unloaded and the "1H on a Two-handed weapon" warnings stay as words in the warning ink on the row.
- **No delete on the row in play** (takeaways 6, 12): edit and remove move to a right-click menu (or a ⋮), with Send to chat; the row keeps the verbs used each session (where it is, quantity, Reload).
- **Quantity**: a small number with − and + (takeaway 8), not an input box; typing stays possible on a click. Weight is shown as a total in the section header or on the Coins line, not as a bar (2d12 tracks weight loosely; players ignore encumbrance math, takeaway 10). A bar only if a rule ever makes a limit bite.
- **The add links** (takeaway 11): the two buttons become a line of links in the NPC sheet's style (`ps2-links`): *Generate Weapon · Browse compendium · New Item*, at the top of the tab (or under the section each one fills). Drag and drop stays the first way in, and the empty sections say so in one line.
- **The Loot tab in the same look** (takeaways 13, 14): the same rows (name, Qty, a muted note) with one verb on the row, *Give…*, and a count when Qty > 1 (pf2e's transfer dialog; today's giveLoot moves the whole stack). Later and only if Lucas wants it: the defeated NPC's loot opened to players (pf2e's lootable NPC), or "Give all to…". The chat line on a give (a `sysLine`) is already there.
- **Not taken:** a grid or paper-doll inventory (takeaway 7), per-item images as big tiles, colored state chips, a capacity bar per container before 2d12 has container rules.
